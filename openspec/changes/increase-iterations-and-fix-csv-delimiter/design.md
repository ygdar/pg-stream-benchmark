## Context

Бенчмарк (BenchmarkDotNet) конфигурирует Job в `Program.cs`. Для не-validation режимов (`dev`/`full`) задаётся явный набор итераций `ShortRun.WithWarmupCount(1).WithIterationCount(2)`. Из-за малого числа замеров оценки для отчёта менее стабильны.

Сводный отчёт генерируется в `Metrics/SummaryReport.cs`. Запись `summary.csv` выполняется через `CsvWriter` с конфигурацией `new CsvConfiguration(CultureInfo.InvariantCulture)`. CsvHelper по умолчанию берёт разделитель из `TextInfo.ListSeparator` культуры конфигурации; на машинах, где инвариантная/системная культура процесса отдаёт `;`, `summary.csv` пишется с `;`, что противоречит ожидаемому `,`.

## Goals / Non-Goals

**Goals:**
- Увеличить число измерительных итераций для dev/full (2 → 12) для повышения стабильности оценок.
- Гарантировать, что `summary.csv` всегда используется `,` в качестве разделителя, на любой машине.
- Минимальные изменения в коде, не затрагивающие метрики, генерацию данных и TSV.

**Non-Goals:**
- Изменение режима `validation` (оставляем штатный `ShortRun`).
- Перестройка механизма ресурс-метрик, генерации TSV и внутреннего формата JSON.
- Изменение заголовков/значений отчёта (только разделитель).

## Decisions

### D1: Увеличить `IterationCount` до 12 в конфигурации Job
В `Program.cs` для не-validation ветки менять `.WithIterationCount(2)` → `.WithIterationCount(12)`, сохраняя `WithWarmupCount(1)`.
*Обоснование:* рост числа замеров ~в 6 раз ощутимо повышает устойчивость статистики при умеренном росте времени прогона; меню `ShortRun` как база сохраняется.
*Альтернативы:* `DefaultJob` — отклонено (сложнее контролировать точное число итераций и число warmup-прогонов); полный набор итераций BDN — избыточно для медиум/больших объёмов.

### D2: Явно задать `Delimiter = ","` в конфигурации `CsvWriter`
В `Metrics/SummaryReport.cs` конфигурацию для записи `summary.csv` строить с `Delimiter = ","` поверх `CultureInfo.InvariantCulture`.
*Обоснование:* явный `Delimiter` перекрывает поведение по умолчанию (зависимое от `ListSeparator` культуры) и даёт детерминированный вывод на всех машинах, независимо от локального положения.
*Альтернатива:* полагаться на `InvariantCulture` (неявно всегда `,`) — отклонено, т.к. на практике машина за счёт системной/процессной локали получает `;`.

## Risks / Trade-offs

- [Рост времени прогона dev/full] → Увеличение итераций 2→12 умножает время замеров примерно ×6; смягчается тем, что dev/full запускаются нечасто, а точность оценок — основной мотив.
- [Читатели `summary.csv`, ломавшиеся на `;`-системах] → Фикс переводит их на `,`; разделитель фиксируется в README/документации как контракт.
- [Дублирование конфигурации CSV при чтении тайминга BDN] → `ReadTiming` читает `*-report.csv` (вывод BDN), их разделитель мы не меняем; явный `Delimiter` задаётся только для записи `summary.csv`.

## Migration Plan

- В `Program.cs`: `WithIterationCount(2)` → `WithIterationCount(12)`.
- В `Metrics/SummaryReport.cs`: конфигурация `CsvWriter` для `summary.csv` с `Delimiter = ","`.
- Прогнать `--mode=validation` и убедиться, что `summary.csv` в `BenchmarkDotNet.Artifacts/results/` начинается со строки «Стратегия,Строк,…», разделённой запятыми.
- Откат: вернуть значения 2 и убрать `Delimiter`; никакой миграции данных не требуется.
