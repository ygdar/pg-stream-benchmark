## Why

Прогоны dev/full используют всего 2 измерительные итерации на бенчмарк, что даёт недостаточно стабильные оценки времени для отчёта. Кроме того, разделитель полей в `summary.csv` не задан явно: CsvHelper по умолчанию берёт `ListSeparator` культуры процесса, поэтому на машинах с русской локалью отчёты пишутся с `;`, тогда как ожидается `,`.

## What Changes

- Количество измерительных итераций (`IterationCount`) для бенчмарков в режимах `dev` и `full` увеличивается с **2 до 12** для повышения надёжности/повторяемости оценок. Режим `validation` не меняется (остаётся штатный `Job.ShortRun`).
- В `summary.csv` разделитель полей **фиксируется явно на `,`**, независимо от региональных настроек машины/культуры процесса. На машинах с `;`-локалью отчёт больше не будет писать `;`.

## Capabilities

### New Capabilities

- `benchmark-run-iterations`: число измерительных итераций для бенчмарков в режимах dev/full равно 12; режим validation сохраняет штатное поведение BenchmarkDotNet.
- `csv-report-delimiter`: сводный отчёт `summary.csv` всегда использует запятую (`,`) как разделитель полей, независимо от культуры процесса.

## Impact

- **Код**:
  - `Program.cs` — значение `.WithIterationCount(...)` в конфигурации Job для не-validation режимов (2 → 12).
  - `Metrics/SummaryReport.cs` — конфигурация `CsvWriter` для `summary.csv`: явно задать `Delimiter = ","`.
- **Время прогона**: dev/full будут выполняться дольше (~в 6 раз больше замеров), снижается ресурсоёмкость механизма BenchmarkDotNet-статистики, но растёт точность.
- **Формат данных**: `summary.csv` детерминированно разделяется запятыми на любых машинах; значения не меняются — только разделитель.
- **Обратная совместимость**: только для читателей `summary.csv` с систем, где раньше использовался `;` — теперь `,` (задокументированный фикс).
- **Внутренние данные**: JSON-метрики и TSV (строго табуляция) не затрагиваются.
