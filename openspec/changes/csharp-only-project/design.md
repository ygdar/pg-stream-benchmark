## Context

Проект — бенчмарк стратегий потоковой/батчевой вставки TSV в PostgreSQL, реализуемый на C# (.NET). Текущий стек: один csproj, BenchmarkDotNet, Npgsql, LINQ2DB, EF Core, AutoFixture, CsvHelper. Проект greenfield и трактуется как C# с самого начала. Ограничение стека (только C#) существовало неявно; задача — сделать его явным и зафиксировать как норму, чтобы исключить случайное привнесение Java и неправильную ассоциацию LINQ2DB с JVM-стеком.

## Goals / Non-Goals

**Goals:**
- Зафиксировать в спецификации и README обязательные ограничения стека: только C# (.NET), запрет Java, linq2db — исключительно C#-библиотека из https://github.com/linq2db/linq2db.
- Дать проверяемые (SHALL/SHALL NOT) требования для код-ревью и аудита репозитория.
- Покрыть весь проект: код, зависимости, скрипты, документация.

**Non-Goals:**
- Изменение требований бенчмарка вставки (`insert-benchmark`).
- Изменение существующего кода — это чисто документационно-нормативное изменение.
- Кросс-платформенные вопросы .NET (например, не вводится требование к конкретной ОС, кроме существующей Windows+докер-среды).

## Decisions

### D1: Ограничение стека — отдельная capability
Вводится новая capability `project-language-constraints` вместо внесения требований в capability бенчмарка.
*Обоснование:* ограничение применяется ко всему проекту в целом, не только к бенчмарку вставки; выделение в собственную capability делает его независимым от scope конкретной фичи и применимым при будущих экспериментах.
*Альтернативы:* встроить в `insert-benchmark` — отклонено: смешивает доменные требования с горизонтальным ограничением стека.

### D2: linq2db фиксируется через официальный репозиторий
Первоисточник linq2db — https://github.com/linq2db/linq2db (C#), подключается как NuGet-пакет, используется из C#.
*Обоснование:* устраняет путаницу с Java/JVM, которую LINQ2DB может вызывать по названию.
*Альтернативы:* не фиксировать происхождение — отклонено: оставляет риск неправильной ассоциации.

### D3: Запрет Java формулируется как SHALL NOT, всеохватывающе
Java/JVM/Kotlin/Groovy/Scala, Maven/Gradle, Java-библиотеки и Java-документация запрещены во всём репозитории.
*Обоснование:* категоричный запрет проще проверять и он не оставляет лазеек для «случайного» привнесения Java.

### D4: Документация в README
README.md получает раздел со стеком и запретом Java, включая ссылку на официальный репозиторий linq2db.
*Обоснование:* для будущих контрибьюторов правило видно сразу, не только в planning-спецификациях.

## Risks / Trade-offs

- **[Ложное срабатывание аудита при схожих именах]** → Требования явно перечисляют, что искать (Java-исходники, JVM-конфиги, Maven/Gradle, Java-зависимости), отделяя от C#-артефактов.
- **[linq2db путают с Java по названию]** → В спецификации и README зафиксирован официальный C#-репозиторий и категорическое «не Java».
- **[Изменение может показаться тривиальным]** → Оно намеренно нормативное: создаёт официальный контракт, по которому код-ревью и планировка следующих изменений отбраковывают Java.
- **[Ретроспективное применение]** → Проверка текущих артефактов (проект и планировка) на отсутствие Java; на данный момент нарушений нет.

## Migration Plan

- Добавить capability `project-language-constraints` в спеки и статью в README.
- Проверить существующие артефакты (benchmark/, README.md, openspec/changes/*) на отсутствие Java-компонентов; при обнаружении — исправить.
- Нет runtime-развёртывания/отката — изменение документационно-нормативного характера.
