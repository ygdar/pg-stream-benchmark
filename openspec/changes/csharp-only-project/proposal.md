## Why

Данный проект — бенчмарк стратегий потоковой/батчевой вставки TSV в PostgreSQL — **по построению является C# (.NET) проектом**: один csproj, BenchmarkDotNet, Npgsql, LINQ2DB, EF Core, AutoFixture, CsvHelper. Существует риск, что при развитии (новые стратегии, модели, эксперименты) в код или документацию будет случайно привнесён Java: LINQ2DB часто ошибочно ассоциируют с JVM-стеком. Чтобы исключить такую путаницу и зафиксировать границы стека как **явное требование**, а не как подразумеваемое допущение, необходимо задокументировать и закрепить правило: весь проект — только C#, Java категорически запрещена.

## What Changes

- Документируются и закрепляются обязательные ограничения стека для всего репозитория:
  - весь проект SHALL быть реализован **только на C# (.NET)**;
  - Java (JVM, Kotlin, Java-стек, Java-библиотеки/инструменты) **категорически запрещена** в любом виде — код, зависимости, скрипты, документация;
  - **linq2db** — это **только и исключительно C#-библиотека** доступа к данным, официальный источник — https://github.com/linq2db/linq2db ; она не является Java-библиотекой и не имеет никакого отношения к Java/JVM.
- Ограничения добавляются в спецификацию проекта как отдельная capability с проверяемыми `SHALL`/`SHALL NOT` требованиями.
- В README проекта добавляется явный раздел, фиксирующий стек (только C#/) и запрет Java с указанием первоисточника linq2db.
- Правило применяется ретроспективно ко всем существующим артефактам: проверяется, что проект и его планировка не содержат Java-кода/зависимостей.

## Impact

- **Язык/стек**: жёсткое ограничение на **C# (.NET)**; запрещены Java/JVM/Kotlin в коде, зависимостях, скриптах и документации.
- **Документация**: README.md — новый раздел о стеке и запрете Java; фиксация первоисточника linq2db (https://github.com/linq2db/linq2db).
- **Спецификации**: новая capability `project-language-constraints` с проверяемыми требованиями.
- **Код**: без изменений кода; чисто документационно-нормативное изменение для закрепления существующего положения дел.
- **Не является изменением требований бенчмарка вставки** — ограничения стека применяются ко всему проекту в целом.
