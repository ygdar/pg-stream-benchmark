## ADDED Requirements

### Requirement: Стратегии вставки
Бенчмарк SHALL сравнивать относительное время следующих стратегий загрузки одного и того же TSV-файла в PostgreSQL: raw multi-row INSERT через npgsql, raw BINARY COPY через npgsql, LINQ2DB BulkCopy (BulkCopyType.ProviderSpecific), стоковый EF Core chunk (SaveChanges), нативный серверный COPY средствами PostgreSQL.

#### Scenario: Все стратегии подключены
- **WHEN** запускается полный прогон бенчмарка
- **THEN** каждая из пяти стратегий (raw batch, raw copy, LINQ2DB, EF chunk, native copy) выполняется и попадает в результат

#### Scenario: Один источник данных
- **WHEN** бенчмарк выполняет загрузку
- **THEN** все стратегии читают один и тот же сгенерированный TSV-файл

#### Scenario: Общий базовый интерфейс
- **WHEN** добавляется новая стратегия
- **THEN** она реализует общий интерфейс `InsertStrategy` и подключается без изменения остальных стратегий

### Requirement: Модель данных как C# класс
Модель данных SHALL быть определена как отдельный C# класс `DataRecord`, являющийся единственным источником структуры для всех стеков (EF, LINQ2DB, raw). Генерация данных SHALL использовать AutoFixture с фиксированным seed, сериализация в TSV — CsvHelper.

#### Scenario: Единая модель
- **WHEN** изменяется структура данных
- **THEN** правило затрагивает один класс `DataRecord` и его маппинг колонок, не меняя каркас бенчмарка

#### Scenario: Детерминированная генерация
- **WHEN** генерация данных выполняется дважды с одним seed
- **THEN** результат идентичен

#### Scenario: CsvHelper только в генерации
- **WHEN** выполняется парсинг TSV при загрузке
- **THEN** используется source-generated regex (`[GeneratedRegex]`), а не CsvHelper

### Requirement: Параметризация размера данных
Число строк в наборе данных SHALL быть параметром бенчмарка со значениями 1 000 000, 2 000 000, 5 000 000, 10 000 000 и 30 000 000. Бенчмарк SHALL поддерживать три режима запуска: validation (1K/10K строк — только для проверки работоспособности во время разработки), dev (1M/2M) и full (5M/10M/30M).

#### Scenario: Все размеры в матрице
- **WHEN** запускается полная матрица
- **THEN** бенчмарк интерполирует по всем пяти значениям размера данных как по `[Params]`

#### Scenario: Режим validation
- **WHEN** запускается режим validation
- **THEN** выполняются только малые размеры (1 000, 10 000 строк) для быстрой проверки работоспособности бенчмарка в процессе разработки

#### Scenario: Режим dev
- **WHEN** запускается режим dev
- **THEN** выполняются только быстрые размеры (1M, 2M) для проверки логики

### Requirement: Окружение PostgreSQL из Docker
PostgreSQL SHALL запускаться из Docker (последняя версия, максимально дефолтная конфигурация). Настройка БД SHALL быть вне тайминга бенчмарка. Каждый прогон SHALL очищать таблицу (TRUNCATE), чтобы начальное состояние было идентичным.

#### Scenario: Поднятие БД
- **WHEN** выполняется настройка окружения
- **THEN** PostgreSQL поднят из docker-compose, готовность подтверждена healthcheck, настройка выполняется до начала замеров

#### Scenario: Очистка между прогонами
- **WHEN** начинается новый прогон стратегии
- **THEN** целевая таблица очищается, состояние идентично предыдущему

### Requirement: Валидация результата
Каждый прогон SHALL проверять, что число загруженных строк совпадает с числом строк в файле.

#### Scenario: Успешная загрузка
- **WHEN** стратегия завершает загрузку
- **THEN** количество строк в таблице равно количеству строк в файле

#### Scenario: Неполная загрузка
- **WHEN** количество строк в таблице не равно количеству строк в файле
- **THEN** результат помечается как невалидный и не учитывается в сравнении

### Requirement: Нативный серверный COPY
Бенчмарк нативного server-side COPY SHALL загружать TSV-файл средствами PostgreSQL и требовать доступ к файлу внутри контейнера (volume) и необходимые права (`pg_read_server_files`/суперпользователь). Подготовка этого доступа SHALL выполняться вне тайминга.

#### Scenario: Файл доступен серверу
- **WHEN** выполняется нативный COPY
- **THEN** TSV-файл смонтирован внутрь контейнера PostgreSQL и доступен процессу сервера

#### Scenario: Права настроены
- **WHEN** выполняется нативный COPY
- **THEN** право `pg_read_server_files` (или суперпользователь) настроено в setup, вне замера
