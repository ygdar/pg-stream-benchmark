## ADDED Requirements

### Requirement: Отбор стратегий через BenchmarkSwitcher
Входная точка бенчмарка SHALL использовать BenchmarkSwitcher для разрешения запускаемых стратегий, а не жёсткий цикл по захардкоденному списку типов. Передаваемые аргументы командной строки SHALL передаваться в `switcher.Run(args, config)` для нативного отбора через `--filter`.

#### Scenario: Запуск конкретной стратегии
- **WHEN** бенчмарк запускается с `--filter "*RawCopy*"`
- **THEN** выполняется только стратегия RawCopy, прочие стратегии не запускаются

#### Scenario: Запуск подмножества стратегий
- **WHEN** бенчмарк запускается с `--filter "*BatchInsert*|*NativeCopy*"`
- **THEN** выполняются только указанные стратегии

#### Scenario: Запуск всех стратегий по умолчанию
- **WHEN** бенчмарк запускается без `--filter`
- **THEN** выполняются все пять стратегий (как и до изменения)

#### Scenario: Перечисление бенчмарков
- **WHEN** бенчмарк запускается с `--list flat` или `--list tree`
- **THEN** BenchmarkSwitcher выводит список доступных бенчмарков без их запуска

### Requirement: Сохранение режима и размеров данных
Отбор через BenchmarkSwitcher SHALL NOT менять управление размерами и режимом: размеры данных SHALL оставаться привязанными к `--mode` через `RunArgs.Sizes`, а выбор Job (число итераций) SHALL по-прежнему определяться режимом. Путь к данным SHALL передаваться дочерним процессам через env-переменную `DBBENCH_DATA_DIR`.

#### Scenario: Режим задаёт размеры
- **WHEN** бенчмарк запускается с `--mode=dev --filter "*RawCopy*"`
- **THEN** выполняется RawCopy только на размерах dev-режима (1M/2M), и файлы генерируются в каталоге `DBBENCH_DATA_DIR`

#### Scenario: Декларативные бенчмарк-классы не меняются
- **WHEN** применяется отбор через switcher
- **THEN** benchmark-классы сохраняют декларативное описание (`[Benchmark]`, `[GlobalSetup]`, `[ParamsSource]`) без функциональных правок
